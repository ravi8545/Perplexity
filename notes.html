🚀 Perplexity Clone - Interview Prep Notes

Aapke project ke liye tayar kiye gaye 20 Basic aur 15 Advanced Technical Questions & Answers

Q1
Apne project ke bare me bataiye (Project Overview & Elevator Pitch)
Basic

💬 Answer:

"Mera project ek AI-Powered Search & PDF Chat Application hai, jo Perplexity AI se inspired hai.

Isme 3 main key features hain:

  • Real-time Web Search: Jab user koi latest news ya current affair ka sawaal puchta hai, toh app internet se fresh data search karke accurate answer deti hai.
  • PDF Chat (RAG): User chat me PDF document upload karke us document ke bare me sawaal puch sakta hai, aur AI sirf us PDF ke facts ke basis par jawab deti hai.
  • Secure Authentication: Isme Email/Password aur 'Sign in with Google' dono support hain, aur Logout ke waqt Redis use karke JWT token ko security ke liye blacklist kiya jata hai.

Iss project ko maine MERN Stack (MongoDB, Express, React, Node.js), LangChain, Pinecone Vector DB, aur Gemini/Mistral AI models ka use karke banaya hai."

Q2
LangChain kya hai aur aapne iska use kyu kiya?
Basic

💬 Answer:

"LangChain ek popular framework/tool hai jo Large Language Models (LLMs) jaise Gemini ya OpenAI ko hamare application code aur external tools se connect karne me help karta hai.

Maine LangChain ka use 2 main reasons ke liye kiya:

  1. Tool Integration: LangChain ke dwara maine AI model ko Internet Search (Tavily API) se joda, taaki AI zaroorat padne par khud internet search kar sake.
  2. Prompt Management: System Prompts, PDF Excerpts, aur User History ko systematically format karke LLM ko bhejane ka kaam LangChain bohot aasani se kar deta hai."
Q3
RAG (Retrieval-Augmented Generation) kya hota hai aur yeh simple words me kaise kaam karta hai?
Basic

💬 Answer:

"RAG ka simple matlab hai 'AI ko bahar se extra information dekar sahi answer nikalwana'.

Standard AI models (jaise ChatGPT) ke paas aapke private PDF file ka data nahi hota. RAG me:

  1. Pehle hum PDF ke text ko chhote-chhote tukdon (Chunks) me todte hain.
  2. Jab user koi sawaal puchta hai, toh hum PDF ke unhi 2-3 sabse relevant chunks ko dhundhte hain.
  3. Us relevant text ko AI ke prompt me chipka dete hain aur AI se kehte hain — 'Is text ko padho aur user ke sawaal ka jawab do'. Isse AI bina hallucinations ke bilkul accurate answer deta hai.
Q4
Vector Database (Pinecone) kya hai aur hum simple database (jaise MongoDB) ke bajaye vector DB kyu use karte hain?
Basic

💬 Answer:

"MongoDB jaise databases exact text match dhundhte hain (keyword search). Lekin agar user ne alag words use kiye lekin matlab same ho, toh traditional DB fail ho jata hai.

Vector Database (Pinecone) text ke Matlab (Meaning / Semantics) ko numbers (Vectors) ke form me store karta hai.

Iska fayda yeh hota hai ki agar PDF me likha hai 'Car' aur user ne pucha 'Automobile', toh Pinecone samajh jata hai ki dono ka matlab same hai aur sahi text search karke dedeta hai."

Q5
Embeddings kya hote hain?
Basic

💬 Answer:

"Embeddings ka matlab hota hai Text ko Mathematical Numbers (Array of Floats) me convert karna.

AI models words ko directly nahi samajhte, wo maths aur vectors samajhte hain. Jab hum kisi sentence ko embedding model (jaise mistral-embed) me bhejte hain, toh wo us sentence ke meaning ke hisab se 1024 numbers ki ek list bana deta hai. Similar meaning wale sentences ke numbers aapas me pass (close) hote hain."

Q6
Gemini aur Mistral AI me kya farak hai aur aapne dono ko kyu use kiya?
Basic

💬 Answer:

"Dono alag-alag AI models hain aur maine dono ko unki strengths ke hisab se use kiya:

  • Gemini (Google): Yeh bohot fast hai aur web search tools ke sath bohot achhe se integrate hota hai, isliye main chat response aur search ke liye Gemini 2.5 Flash use kar raha hu.
  • Mistral AI: Iska embedding model (mistral-embed) PDF text ko vectors me convert karne ke liye bohot accurate hai, aur iska chhota model (mistral-small) chat ka title generate karne me fast hai.
Q7
JWT (JSON Web Token) kya hai aur authentication me iska kya role hai?
Basic

💬 Answer:

"JWT ek digital pass/identity card ki tarah hota hai. Jab user login karta hai, toh server user ke data (like userId) ko encrypt karke ek encrypted string (Token) generate karta hai aur client ko bhej deta hai.

Next time jab bhi client koi request karta hai, wo yeh Token saath me bhejta hai. Server token ko verify karke samajh jata hai ki user logged in hai. Isse baar-baar password daalne ki zaroorat nahi padti."

Q8
Redis kya hai aur aapne logout function me Redis kyu use kiya?
Basic

💬 Answer:

"Redis ek ultra-fast In-Memory Key-Value Database hai jo RAM me data store karta hai.

JWT Tokens ki problem yeh hoti hai ki expiry se pehle unhe server-side se directly cancel nahi kiya ja sakta. Maine Logout security ke liye Redis use kiya:

  • Jab user Logout button par click karta hai, toh uske token ko hum Redis me blacklisted mark karke store kar dete hain.
  • Next time agar koi us token se request karega, toh middleware Redis me check karke access deny kar dega.
Q9
Google Sign-In (OAuth) kaise kaam karta hai aapke project me?
Basic

💬 Answer:

  1. Frontend par user Google ke popup se apna account select karta hai, jahan se ek Google ID Token milti hai.
  2. Frontend yeh ID Token humare backend API ko bhejta hai.
  3. Backend par google-auth-library us token ko Google se verify karti hai.
  4. Verification ke baad agar user humare database me pehle se hai toh direct login ho jata hai, aur agar naya hai toh automatic naya account create ho jata hai.
Q10
Socket.io kya hota hai aur iska use chat application me kyu hota hai?
Basic

💬 Answer:

"Normal HTTP requests me client ko baar-baar server se puchna padta hai (Request-Response).

Socket.io WebSocket protocol par kaam karta hai jo client aur server ke beech ek 2-Way Continuous Connection bana deta hai. Isse bina page refresh kiye ya bina baar-baar request bheje, server real-time me instant messages client tak bhej sakta hai."

Q11
Redux Toolkit kya hai aur React me state management ke liye iska use kyu kiya?
Basic

💬 Answer:

"Redux Toolkit ek global state management library hai.

Jab application me bohot saare pages hote hain (jaise Login, Chat, Upload Status), toh data ko ek component se dusre component me pass karna mushkil ho jata hai (Prop Drilling). Redux ek Centralized Store bana deta hai jahan se koi bhi component directly state read aur update kar sakta hai."

Q12
ImageKit kya hai aur PDFs upload karne ke liye iska use kyu kiya?
Basic

PDFs ko direct MongoDB me store karne se database heavy aur slow ho jata hai. Isliye PDF files ko ImageKit par upload karke unka permanent Cloud URL le liya jata hai, aur MongoDB me sirf us URL ko store kiya jata hai."

Q13
Tavily API kya hai aur yeh web search me kaise help karti hai?
Basic

💬 Answer:

"Tavily ek specialized Search API hai jo AI applications ke liye design ki gayi hai. Normal Google search HTML web pages return karta hai, lekin Tavily search query par internet se sirf clean, structured aur factual text summaries return karta hai jisse AI easily padh kar answer bana sake."

Q14
Express Middleware kya hota hai aur authUser middleware ka kya kaam hai?
Basic

💬 Answer:

"Express me Middleware ek aisa function hota hai jo request ke Controller tak pahunchne se pehle beech me execute hota hai.

Humara authUser middleware har protected request ko check karta hai:

  1. Browser Cookie se JWT Token nikalta hai.
  2. Token ki validity verify karta hai.
  3. Redis me check karta hai ki token blacklisted toh nahi hai.

Agar sab sahi hai tabhi request ko aage jane deta hai (next()), varna 401 Unauthorized error de deta hai."

Q15
Iss project ko banane me aapko sabse badi challenge kya aayi aur aapne use kaise solve kiya?
Basic

💬 Answer:

"Sabse badi challenge thi PDF Text Retrieval accuracy:

Shuruat me PDF upload hone par kabhi-kabhi AI irrelevant answer de deta tha. Maine isko solve karne ke liye 2 cheezein fix ki:

  1. Chunking Strategy: Chunk size ko 400 characters aur 50 overlap par fine-tune kiya taaki context break na ho.
  2. Pinecone Namespaces: Har chat ID ke liye dedicated Pinecone namespace banaya taaki ek user ki PDF ka data kisi dusre user ke query me mix na ho. Isse accuracy 100% resolve ho gayi."
Q16
CORS (Cross-Origin Resource Sharing) kya hota hai aur isse project me kaise handle kiya?
Basic

💬 Answer:

"CORS browser ka ek security mechanism hai jo rokta hai ki ek origin (domain/port) par chalne wala frontend kisi dusre origin ke backend se unauthorized HTTP requests na kar sake.

Humara Frontend localhost:5173 (Vite) par chal raha tha aur Backend localhost:3000 par. Is Cross-Origin issue ko fix karne ke liye backend me cors middleware use kiya:

app.use(cors({
  origin: process.env.FRONTEND_URL,
  credentials: true // Cookies pass karne ke liye
}));

Isse Browser authorized backend responses receive karne lagta hai."

Q18
Express me req.body, req.params, aur req.query me kya fark hota hai?
Basic

💬 Answer:

  • req.body: Form ya JSON data ko HTTP POST/PUT request ke payload se read karne ke liye (e.g. req.body.message).
  • req.params: Route URL ke dynamic parameters ko read karne ke liye (e.g. /api/chats/:chatId me req.params.chatId).
  • req.query: URL ke query strings ko read karne ke liye (e.g. /api/chats?page=1 me req.query.page).
Q19
React me useState aur useEffect Hooks ka kya role hai aapke project me?
Basic

💬 Answer:

  • useState: Local component level state manage karne ke liye use hota hai (jaise user input field ka text, attached PDF file object, ya loading spinner open/close status).
  • useEffect: Component Lifecycle ke side-effects handle karne ke liye use hota hai (jaise Component mount hote hi user ke chat history ko backend API se fetch karna, ya WebSocket connection initialize karna).
Q20
Axios vs Native Fetch API: Aapne Axios kyu prefer kiya?
Basic

💬 Answer:

"Native fetch() ke mukable Axios ke 3 major benefits hain jo maine use kiye:

  1. Automatic JSON Parsing: Axios response Data ko automatically JSON me parse karta hai (manual res.json() ki zaroorat nahi padti).
  2. Easy Cookie Handling: Axios instance me withCredentials: true globally set kar sakte hain HTTP-Only cookies send karne ke liye.
  3. Better Error Handling & Interceptors: Non-2xx HTTP status codes (jaise 401, 500) par Axios automatically catch block throw karta hai."
AQ1
PDF RAG ka exact architecture aur pipeline code level par samjhao.
Advanced
💡 Interviewer Intent: Code-level pipeline execution samajhna.

Ingestion: Multer buffer $\rightarrow$ ImageKit CDN upload $\rightarrow$ pdf-parse text extraction $\rightarrow$ RecursiveCharacterTextSplitter (400 size, 50 overlap) $\rightarrow$ mistral-embed (1024-dim) $\rightarrow$ Pinecone namespace (chatId).

Query: Embed user query $\rightarrow$ Pinecone similarity query (topK: 3, threshold > 0.3) $\rightarrow$ Inject chunks in System Prompt $\rightarrow$ Gemini Flash response generation.

AQ2
RecursiveCharacterTextSplitter, Chunk Size 400 & Overlap 50 ka rationale.
Advanced
💡 Interviewer Intent: Context retention vs vector search accuracy trade-offs.

Hierarchical splitting (\n\n, \n, space) preserves structural boundaries. 400 chars ensures narrow, high-density vector representation in mistral-embed. 50 char overlap prevents loss of context at sentence boundaries.

AQ3
Pinecone namespace(chatId) multitenancy design.
Advanced
💡 Interviewer Intent: Data isolation and query performance.

Using pdfIndex.namespace(chatId) restricts vector search to the exact chat session. Eliminates cross-chat data leaks and reduces vector search space to sub-millisecond execution times.

AQ7
Redis Token Blacklisting implementation on Logout.
Advanced
💡 Interviewer Intent: Stateless JWT revocation handling.

On /logout, token stored in Redis: redis.set(token, 'blacklisted', 'EX', ttl). authUser middleware queries Redis on every request; if token exists in Redis blacklist, request is rejected with HTTP 401.

AQ8
Google OAuth Server-side verification flow.
Advanced
💡 Interviewer Intent: Secure OAuth token validation.

Frontend sends GSI ID Token to backend. google-auth-library verifies token signature via OAuth2Client.verifyIdToken(). Email extracted $\rightarrow$ Auto-register user or log in $\rightarrow$ Issue HTTP-Only JWT cookie.

AQ9
HTTP-Only Cookies vs LocalStorage for JWT storage.
Advanced
💡 Interviewer Intent: XSS vs CSRF mitigation awareness.

LocalStorage is vulnerable to XSS script reading. HTTP-Only cookies (httpOnly: true, secure: true, sameSite) prevent JavaScript access, eliminating XSS token theft. Sent automatically via Axios withCredentials: true.

AQ10
ImageKit + Pinecone vs Direct MongoDB binary storage.
Advanced
💡 Interviewer Intent: Separation of Concerns & Storage Optimization.

PDF binary blobs bloat MongoDB BSON 16MB limit and cause memory spikes. Separation: ImageKit for CDN asset delivery, Pinecone for vector math & similarity search, MongoDB for lightweight metadata.

MongoDB Data Relationship & Indexing design.
Advanced
💡 Interviewer Intent: Schema design & database execution plan.

User, Chat, and Message collections linked via ObjectId references. MessageSchema indexes chat field to optimize chronological message fetching (find({ chat: chatId }).sort({ createdAt: 1 })).
